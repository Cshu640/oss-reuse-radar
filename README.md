# OpenRadar · 开源项目雷达

面向个人、独立开发者与 Codex 工作流的跨平台开源项目发现、搜索、收藏与历史增长雷达。

## Phase 0.3-A

当前版本已经具备两条主线：

1. **五个平台实时项目数据**
   - GitHub
   - Hugging Face
   - GitLab
   - Codeberg
   - ModelScope
2. **零依赖本地历史快照**
   - `node server.mjs` 启动后立即采集
   - 之后每6小时自动采集一次
   - 本地保存 Stars、Forks、Likes、Downloads 历史
   - 历史跨度足够后，显示真实24小时、7天与30天增长

Gitee仍保留在产品中，但已执行明确止损：

```text
Gitee v5 API
  ↓ 空结果或失败
Gitee官方搜索页
  ↓ 无法解析项目
Gitee公开探索页（仅首页雷达）
  ↓ 仍无结果
外部搜索入口
```

Gitee处于“外部搜索”状态时，不计入实时平台数量，不参与榜单或增长统计，也不会拖累其他平台。

## 核心功能

- 今日/24小时、7天、30天增长入口
- 低 Star 高潜力代理榜
- 中文自然语言需求扩展为英文技术关键词
- 跨平台并行搜索
- 办公效率、生活工具、商业应用底座等分类
- 许可证、平台与用途筛选
- 收藏、标签、备注与下一步动作
- 收藏JSON导出
- Windows桌面PWA安装
- 本地历史状态面板与手动立即采集
- 后台采集失败隔离：单个平台失败不清空其他结果

## 推荐启动方式

必须进入包含 `index.html`、`server.mjs` 的 `open-source-radar` 文件夹。

### Windows最简单

双击：

```text
start-openradar.cmd
```

### 命令行

```bash
node server.mjs
```

然后打开：

```text
http://localhost:8080
```

终端必须保持打开。按 `Ctrl + C` 停止服务。

正常启动会显示：

```text
OpenRadar Phase 0.3-A
Local: http://localhost:8080
History: 本地快照已启用（启动即采集，之后每6小时采集五个平台）
```

## 历史快照如何工作

### 自动采集

本地服务器启动后：

1. 立即扫描五个平台候选项目；
2. 将当前指标保存为第一份快照；
3. 每6小时重复采集；
4. 浏览器点击“刷新雷达”时也会补充快照；
5. 相同数据在短时间内会自动去重，避免文件快速膨胀。

### 数据位置

```text
data/history.json
```

该文件：

- 只保存在你的电脑；
- 不提交到Git；
- 不上传到第三方；
- 默认保留约400天；
- 删除后历史会重新从零积累。

### 什么时候能看到真实增长

第一次启动不能凭空生成历史数据。

- 24小时增长：历史跨度达到约20小时后启用；
- 7天增长：历史跨度达到约6天后启用；
- 30天增长：历史跨度达到约25天后启用。

不足时项目卡会明确显示：

```text
积累中
```

不会把潜力代理分冒充成真实涨幅。

### 跨平台排名

不同平台使用不同主指标：

- GitHub / GitLab / Codeberg：Stars
- Hugging Face / ModelScope：Likes或Downloads对应的平台主指标

跨平台榜单先计算各平台内部增长百分位，再进行排序，不直接把“1000次下载”和“100个Star”当成同一个单位比较。项目卡仍显示其原始指标增量，便于理解。

## 本地API

`server.mjs` 提供：

```text
GET  /api/health
GET  /api/gitee/search
GET  /api/history/status
GET  /api/history/growth
POST /api/history/capture
POST /api/history/collect
```

### 手动触发一次后台采集

可以在“观察名单与真实增长”页面点击：

```text
立即采集一次
```

也可以通过本地API调用。

## 静态兼容模式

仍可运行：

```bash
npx --yes serve . -l 8080
```

但静态模式缺少：

- Gitee同源兼容通道；
- 本地历史保存；
- 六小时后台采集；
- 真实增长计算。

因此正式使用应优先运行：

```bash
node server.mjs
```

## 数据与安全约束

- 第一版付费API成本为零；
- 不在前端保存GitHub、Gitee或模型平台Token；
- Gitee服务只访问固定官方域名，不是开放代理；
- 请求有长度、数量、超时与缓存限制；
- 收藏继续使用 `openradar:favorites:v1`；
- 历史文件不包含私有仓库代码，只保存公开项目标识和公开指标；
- 正式采用任何项目之前，仍需人工复核许可证、维护状态与安全风险。

## 当前限制

- 本地服务器关闭期间不会自动采集；真正无人值守需要后续云端部署。
- 初始候选池不是全网全量仓库，榜单描述的是OpenRadar当前追踪项目。
- Gitee官方公开搜索路径持续空结果时，仅提供外部搜索入口。
- 跨平台镜像与同一项目多平台身份尚未完全去重。
- 收藏仍主要保存在当前浏览器，请定期导出JSON。
- 中文搜索扩展是本地规则与多轮检索，不是大模型语义检索。
- 自动分类、用途与许可证元数据仍需人工核查。
